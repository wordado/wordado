# Passkeys Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A learner can add a passkey after an emailed-code sign-in and sign in with it later; settings list and remove passkeys; export and erasure cover them (#287).

**Architecture:** The server mounts Better Auth's passkey plugin beside `emailOTP`, with the relying party from a new `PASSKEY_RP_ID` setting and a migration whose trigger blanks `name` and `aaguid`. The web app calls the plugin's endpoints through its own `httpApi`, with `@simplewebauthn/browser` loaded lazily by the sign-in screen and the account settings.

**Tech Stack:** Better Auth 1.7.5 + `@better-auth/passkey@1.7.5`, `@simplewebauthn/server` 13 (via the plugin) and `@simplewebauthn/browser` 13, Postgres migrations, Hono Worker, React, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-18-passkeys-design.md` (approved 2026-10-18). Parent: `docs/superpowers/specs/2026-09-20-vocabulary-learning-app-design.md` §8.6, §11.

## Global Constraints

- `@better-auth/passkey` pinned to exactly `1.7.5` (server); `@simplewebauthn/browser` `^13.3.0` (web). No Better Auth upgrade.
- RP ID: `config.passkeyRpId`, from `PASSKEY_RP_ID`, else `BASE_URL`'s hostname. `rpName: 'Wordado'`. Expected origin: `BASE_URL`'s origin plus `TRUSTED_ORIGINS`, never the request header.
- `authenticatorSelection: { residentKey: 'required', userVerification: 'required' }`; no attestation.
- `disabledPaths: ['/passkey/update-passkey']`.
- Rate limits: `/passkey/generate-authenticate-options` and `/passkey/verify-authentication` 10 per 60 s; `/passkey/generate-register-options` and `/passkey/verify-registration` 5 per 60 s.
- Stored `name` and `aaguid` are always null (trigger).
- Export format `wordado-export-5`, with `account.passkeys: { createdAt: number }[]` oldest first.
- Every new string in en, de, es, bg (`web/src/i18n/*.ts`), in the style of the neighbours (de: du; es: tú; bg: lower-case `ви` as the app already writes).
- Nothing about passkeys renders where `window.PublicKeyCredential` is undefined.
- Commits as `11029931+danchom@users.noreply.github.com`.

## Review Focus

1. **Passkey sign-in on a device that holds another account's progress** → the same `signin.otherAccount` error as a code sign-in; no merge. Test in Task 5.
2. **Passkey sign-in while a demo with progress is on the device** → the same carry-over or discard as a code sign-in (`completeSignIn`). Test in Task 5.
3. **Learner cancels the device prompt** (`NotAllowedError`) → nothing is said on the sign-in button path; one line on the offer, then onward; the offer is recorded as answered. Tests in Tasks 5 and 4.
4. **The conditional (autofill) request is still pending when the learner presses the passkey button or submits a code** → it is aborted first; no "a request is already pending" error reaches the learner. Test in Task 5.
5. **A removed passkey used again** → server 401 `PASSKEY_NOT_FOUND`; the app shows `signin.passkeyGone`. Tests in Tasks 2 and 5.

### Task 4: The app's passkey calls

**Files:**
- Modify: `web/package.json`, `pnpm-lock.yaml`, `web/src/account/api.ts`, `web/src/account/api.test.ts`
- Create: `web/src/account/passkeys.ts`, `web/src/account/passkeys.test.ts`

**Interfaces:**
- Produces in `api.ts` (`Api`):
  - `passkeyRegister(): Promise<void>` — GET `/api/auth/passkey/generate-register-options`, `startRegistration({ optionsJSON })`, POST `/api/auth/passkey/verify-registration` `{ response }`.
  - `passkeySignIn(options: { conditional: boolean; signal?: AbortSignal }): Promise<void>` — GET `generate-authenticate-options`, `startAuthentication({ optionsJSON, useBrowserAutofill: conditional })`, POST `verify-authentication` `{ response }`.
  - `listPasskeys(): Promise<readonly { id: string; createdAt: number }[]>` (oldest first; drop every other field).
  - `deletePasskey(id: string): Promise<void>`.
  - Errors: `PasskeyCancelled` (the browser's `NotAllowedError` or `AbortError`), `ApiError` with `status === 403` meaning *sign in again first*, `ApiError` with `code === 'PASSKEY_NOT_FOUND'` meaning *gone*.
- Produces in `passkeys.ts`: `passkeysSupported(): boolean`; `platformAuthenticator(): Promise<boolean>`; `conditionalSignIn(): Promise<boolean>`; `offerAnswered(store: KeyValue): boolean` and `markOfferAnswered(store: KeyValue): void` on key `wordado.passkeyOffer`; `signalGone(id: string): void` (calls `PublicKeyCredential.signalUnknownCredential` with the RP ID from the last options when present, else nothing). `@simplewebauthn/browser` is imported with `import()` inside the Api methods only.
